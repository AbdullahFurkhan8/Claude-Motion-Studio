# Code Explainer Video

Working example: `reference-code/touchscreen/` (the full touchscreen video; reuse its `lib.js`, `screens.js`, `captions.js` and `render.js` as is, and write new `scenes.js` for each topic).

## Before building (always ask first)
- **Ask for assets.** Before writing any scene, list the real-world assets the video would benefit from: logos, product photos, screenshots, book covers, short clips (from the reference video or your own plan). Ask the user to supply them as SVG, PNG or video. Use what they give you. For anything they say they can't find, draw your own version in code.
- **Ask about languages.** If the user gives a second voiceover (for example Hindi), build **both versions** from the same scenes: one per voice.

## Using the user's assets
- Put the files in `private/<project>/assets/`. If they come as one collage image, set the boxes in `tools/crop_assets.py` and run `python tools/crop_assets.py collage.png assets/png`. It crops each item, cuts product shots out with `rembg` (`isnet-general-use`, with the matte hardened so white products aren't half transparent) and masks personal names on screenshots. Preview the crops on a mid-grey sheet before using them.
- Generated SVGs often have a backdrop baked in. Delete the background lines and tighten the `viewBox` to get a clean cutout.
- Copy the files you use into `src/assets/`. `assets.js` preloads them (`loadImages([...])` in `main.js`), `img(ctx, name, x, y, w)` draws them centred, and `render.js` serves `.png`/`.svg`. Always wrap images in `alive()` or `flipIn()`.
- `save_to_skill.py` never copies `assets/` or any image into the public skill. The user's images stay private.

## Steps (what was done, in order)
1. **Set up the project** in `private/<project>/` (gitignored). Copy `reference-code/touchscreen/*` there, then run `npm i playwright@1.56`. If Playwright's browser download is missing, set `MVD_CHROMIUM` to an installed `ms-playwright/chromium-*/chrome-win64/chrome.exe`.
2. **Study the reference**: extract the audio as WAV, then make contact sheets with `ffmpeg -i ref.mp4 -vf "fps=2,scale=180:-1,tile=10x3" sheet_%02d.png` and look at the sheets for the visual style and the beat for each word.
3. **Get word timestamps**: run `python tools/transcribe.py <in.wav> <out.json> [lang]`. On an NVIDIA GPU it runs `large-v3-turbo` in float16 (it finds the cuBLAS/cuDNN DLLs inside the CUDA build of torch). After the one-time model download it takes seconds and gives much better Hindi. Without a GPU it falls back to CPU "small". Audio is passed as numpy because the PyAV `open()` call breaks on some machines. Then run `python tools/build_timing.py <v> words.json <duration>` to write `src/timing_<v>.js` with WORDS and caption CHUNKS (≤4 words, split at punctuation or gaps over 0.3 s).
4. **Write scenes** (`src/scenes.js`): one block per narration beat. Every time comes from `c('phrase', after)`, a word cue, and `'a|b'` gives an alternative for script differences. Never hard-code seconds, so the same code fits any voice reading the script. Each scene pushes `sfx` cues next to its visuals.
5. **Motion rules that make it hooky**:
   - Something always moves: a slow camera push (`focus()` plus `kf()` keyframes), plus an "alive" loop such as arcs breathing, travelling charge dots, dust, snow or rain.
   - Cut on the first word of each beat. Start each scene with a 1.1→1 punch-in and a 0.12 s dark fade.
   - Objects enter with easing: `eback` for phones popping up, `eo` for slides, `eio` for camera moves.
   - Each keyword gets a visual action at its exact word time: a label with a leader line, a value dip, a ripple, or a highlight.
   - **No still objects.** Every asset on screen keeps moving: wrap it in `alive()` from `lib.js` (slow pseudo-3D Y turn, bob, breathe, optional spin), bring cards and phones in with `flipIn()`, spin small badges and rings, slide text and bubbles in from the sides, and pulse counters on each change. `main.js` also adds a global camera (slow push-in per scene plus gentle drift), so even the background is never frozen.
   - Use a dark navy gradient background, gold glowing strokes (two strokes with `lighter` compositing), white spaced-caps labels, and small notes such as "Magnified illustration" or "Values illustrative".
   - Captions sit at the top. Words blur in as they are spoken, the current word is bold, and keywords get a blue selection box with corner handles and an optional emoji.
6. **Preview cheaply** with `node src/render.js --v <v> --fps 0.5 --scale .3 --out cache/sheet --jpg`, then tile the frames with `ffmpeg -i cache/sheet/%05d.jpg -vf tile=12x4 sheet.jpg` and look at the sheet. Fix the framing (zoom in if it feels empty) before the full render.
7. **Sound**: run `node tools/export_cues.mjs <v>` to get cue JSON for the scene SFX. Caption keywords get **no** sound by default (`CAPTION_SFX = false` in `scenes.js`), so sound only real on-screen events: cuts, taps and reveals. Never fire trains of small pops, ticks or typing clicks (per counter step, per typed character, per particle): they sound like a droplet that keeps starting and stopping through the whole video. Give a counter, typing run or burst one sound at most, and check the exported cues for runs of more than 3 small hits within a couple of seconds. Rotate variants per kind (for example several whooshes) so repeats don't sound identical. Then run `python tools/mix.py <v> voice.mp3 out.wav`. It aligns each sample's peak to its cue, trims tails, adds procedural rain, and runs loudnorm to -14 LUFS. The kind→file map is at the top of `mix.py` (the `sound-effects/` library).
8. **Final render**: `node src/render.js --v <v> --fps 30 --out renders --name "<Name> v1" --audio out.wav` (1080x1920, H.264 CRF 18, JPEG frame pipe). Never overwrite a version; make v2 instead.
9. **Save the code back**: run `python tools/save_to_skill.py <project-name>`. It copies `src/` and `tools/` into `skills/code-explainer-video/reference-code/<project-name>/` without timing, transcripts or media. Then add one line to the log below.

## Second-language version (Hindi example)
- **Captions are Hinglish by default** (Hindi in Roman letters), which also keeps keyword and cue matching simple.
- Transcribe with `python tools/transcribe.py hi.wav analysis/hi_words.json hi`. Whisper skips or garbles stretches of Hindi, so re-transcribe any gaps in 6–8 s chunks (with `task="translate"` to check meaning). Then write a clean Hinglish script as `start-end | text` lines (segment times from the `.txt`), then run `python tools/align_script.py analysis/hi_words.json analysis/hi_script.txt analysis/hi_clean.json` and `python tools/build_timing.py hi analysis/hi_clean.json <duration>`.
- The scenes stay the same. `scenes.js` exports `LANG.hi.alias`, which maps each English cue phrase to the words the Hindi voice says. `'anchor > phrase'` finds the phrase after an anchor, and `'a|b'` takes the first one found. `LANG.hi.keywords` and `LANG.hi.emoji` cover the captions. Any version name starting with `hi` uses them (`--v hi`).
- **Spoken tags:** TTS voices sometimes read direction tags aloud ("whispers", "excited", "short pause"). Find them in the transcript, leave them out of the captions, and mute those spans in the voice with 20 ms fades before mixing.
- Word order changes in translation. Check that the cue times inside each scene still rise. If they don't, point the alias at a nearby word.
- Hindi version: show the profile picture only, with **no channel name or handle** anywhere (outro card, share sheet, chat).
- Captions use the `"Nirmala UI"` fallback font for Devanagari. Word normalisation keeps letters, combining marks and digits in any script.

## Ending: design a new one for every video
- **Never copy the "made with code" or "comment guide / link in bio" scenes from another project.** Design them fresh around this video's topic and objects, so no two videos end the same way. Example (mac-trackpad): the same laptop from the video shows an editor typing the click logic while a live preview of the video's own cutaway renders beside it, with the real frame number in the status bar. Then "guide" is typed by the laptop's own keys lighting up, posted with a trackpad click (haptic ring), and the bio link gets a force click. Other ideas: an iPhone video ends on its own lock screen or notification, a battery video ends on a charge bar that fills to "100% code".
- **Check the last frames.** Render stills at the code cue and at the final second. The code must finish typing before the scene ends (set the typing speed from the cue gap: `chars / (codeCue - sceneStart)`), and bars and text must sit inside their window at every value (no tiny rounded bars spilling out at 0%).

## Gotchas
- Scripts with a shebang must not have a UTF-8 BOM (PowerShell `Set-Content` adds one), or Node fails.
- Cue errors show up as a renderer `__ready` timeout. Test cues first with `node --input-type=module -e "...makeScenes(makeCue(WORDS))"`.
- Keep the draw code deterministic: everything comes from time T and `hash()`, with no `Math.random` or `Date`.
- A reference video's soundtrack may be used for private study only. Publish only with the user's own voice.

## Presenter + light/dark style (laptop-battery example)
- `char.js` is an original presenter character. Poses (point, stop, think, panic, thumbs and so on) are set on word cues with `pose(t, name)`, and the mouth moves while a word is spoken.
- Each scene is flagged as light or dark. Captions switch to dark text on light scenes, and soft fades keep the top (captions) and bottom (presenter) clean.
- Each project's `scenes.js` exports `KEYWORDS` and `EMOJI`. Both `main.js` and `export_cues.mjs` apply them through `setKeywords()`.
- Never copy a reference creator's mascot or real brand logos. Draw your own versions.
